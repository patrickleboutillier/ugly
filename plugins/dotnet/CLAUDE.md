# The .NET plugin

Notes for Claude Code, loaded when working in this directory. Shared rules: `plugins/CLAUDE.md` and the root `CLAUDE.md`.

**`dotnet/`** is C# on the CLR (.NET 10 SDK, found via `dotnet --list-sdks`; `nethost` from the SDK's apphost pack), language `"dotnet"`.

- `dotnet.c` only starts the CLR: `hostfxr_initialize_for_runtime_config` (`Ugly.runtimeconfig.json`), then `hdt_load_assembly` loads `Ugly.dll` into the *default* load context (the isolated one of `load_assembly_and_get_function_pointer` would give fixture assemblies a second copy of the `Ugly` types), and `hdt_get_function_pointer` fills the vtable with `Ugly.Bridge`'s `[UnmanagedCallersOnly]` methods. `Bridge.Init` gets libugly's handle (`dladdr` on `ugly_export`) for P/Invoke's `"ugly"`.
- Everything else is C#: `Native.cs` (the core's structs and `[DllImport]`s, `DisableRuntimeMarshalling`), `Bridge.cs` (entry points, `Refs`, `Conv`, `Errors`), `Protocol.cs` (reflection, overload scoring, keyword binding, hints, delegates from callables), `Foreign.cs` (`Foreign`, a `DynamicObject`; `ForeignException`; `Interop.Module`/`Eval`; `Ops`; `Loader`).
- One CLR per process, `UGLY_CAP_ANY_THREAD`, nothing else. Refs are counted `GCHandle`s, one per object; the handle's address is the identity. Every entry calls `EnsureSufficientExecutionStack` (.NET can't catch a stack overflow).
- Keyword arguments bind to parameter names (C#'s named and optional arguments); hints are C# aliases or full names (`"int"`, `"System.Int32"`); a hint is refused if the callee turns out to be foreign. `Protocol.Hint` is `[ThreadStatic]` and consumed by `Choose`.
- `Protocol.Iter` wraps an enumerable that is its own enumerator (`yield`, LINQ) in a `Pass`, so each `ugly_iter` is a new pass with its own handle and its own `Dispose()`. `Conv` takes a DOUBLE of a wide integer from its own value (`WideDouble`).
- Entries on a `Foreign` (contract §2): the indexer (`At`/`Put`, `this[object?]`, `TryGetIndex`) is an entry for a keyed collection, an element for an integer on a sequence, else a member by name; `GetEntry`, `SetEntry`... (A C# dictionary as ENTRIES is still to do.)
- Modules are types: by full name in loaded assemblies, then `<longest prefix>.dll` on the module path (`path` option, `UGLY_DOTNET_PATH`) or in the framework, then any assembly on the path. The fixture is `tests/dotnet/conformance.cs`, built into `conformance.dll` against the built `Ugly.dll` (`-p:UglyDll=`).
- Signals: the CLR keeps its fault handlers (SEGV, FPE, ILL, BUS, TRAP) and SIGRTMIN, which chain to earlier handlers; `dn_init` restores SIGINT, SIGQUIT, SIGTERM, SIGPIPE and SIGABRT after starting it. Test `dotnet-signals`.
- Tests are in suite `clr`, kept out of valgrind and helgrind (CI's helgrind step excludes `threads-dotnet`).
- The binding is `Ugly.dll` itself (`Binding.cs`), no native shim: on the first `Interop` call it loads libugly (`UGLY_LIBRARY`, else `libugly.so.2` by the system's search, else beside `Ugly.dll`), builds the `ugly_plugin` vtable in C# (`PluginTable`, field for field with `ugly_plugin.h`: keep them in step) from the same entry points, then `ugly_lang_register` and `ugly_rt_attach` (`Bridge.RtAttach`) on that thread's `ugly_ctx_thread`. `Binding.Embedded` (set by `Bridge.Init`) tells the two modes apart; both share `Binding.UseLibrary` for P/Invoke. Teardown is explicit, `Interop.Shutdown()` on the attaching thread: `ProcessExit` runs on another thread. API: `Interop.Module` (a `Foreign`), `Eval`, `Configure`, `Kw(...)`, `Opts(hint:, context:)` (trailing markers, split in `Ops.Split`), `IsForeign`; through `dynamic`, named arguments are keyword arguments. Calling a `Foreign` class that's INSTANTIABLE but not CALLABLE constructs it (traits cached). Test: `tests/dotnet/binding/test_binding.cs`, run as `dotnet test_binding.dll` with `UGLY_LIBRARY` (suites `bindings`, `clr`); its last line comes from a Lua finalizer at `Shutdown`.

- `Directory.Build.props` sends C# builds made outside Meson (the editor's C# extension, a plain `dotnet build`) to `.artifacts/`; Meson's pass their own `--artifacts-path`.
